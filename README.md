# 麦麦拼单官 · mcd-group-order-mate

> 一群人一起点麦当劳时，帮你**凑满减、算最优券组合、按人分账，并一键下单**。

一个基于**麦当劳 MCP** 与 **WorkBuddy Skill** 的多人拼单助手。

---

## 为什么需要它

办公室里五个人一起点麦当劳，实际流程往往是这样：

1. 群里问一圈"你吃什么"，拼出一份手写清单
2. 打开菜单，把每个人点的东西加进购物车
3. 纠结"我卡包里那几张券用哪张、用在哪个商品上最划算"
4. 终于下单，然后**拿出计算器按人头摊钱**——共享的小食怎么摊？优惠归谁？
5. 有人觉得算错了，群里再扯十分钟

**第 3 步和第 4 步，本该是程序该干的事。**

麦当劳的优惠券是**绑定到具体商品**的，所以"用哪张券"本质上是一个*分配问题*：几张券、几个商品，怎么配才能让总价最低？再加上会员价、随单购价、配送费分摊，手算根本算不过来。

**麦麦拼单官把这两步自动化了。**

## 亮点

### 1. 券与拆单优化，不是"挑一张最大的券"

麦当劳的券**绑定到具体商品**，而且**一张订单只能用一张券**（实测 `600022`）。所以真正的问题是：

> 手上有 N 个人要买的东西、M 张券，**怎么拆成若干单**（每单一张券）让总价最低？

这是一个**二分图最大权匹配**问题：左边是券、右边是"需求份"，边权 = 该券顶替该份能省的金额。项目用**匈牙利算法**求精确最优的用券组合，再派生多套备选拆法，最后把 `calculate-price` 当**唯一可信的价格预言机**逐单真实试算，取真实最低总价。

```
商品原价（不用券）               ¥118.00
★ 拆单用券后                     ¥108.80    省 ¥9.20
──────────────────────────────────────────
 单①「麦旋风任选」  经典麦旋风 ¥15.00 → ¥9.90
 单②「薯薯任选」    薯条       ¥14.00 → ¥9.90
──────────────────────────────────────────
 一单一券（接口限制）；到店自取无配送费，拆单零成本
```

> **为什么是"拆单"而不是"多张券叠一单"？** 因为这是实测结论 —— 官方文档里没写。
> 用真实券跑 `calculate-price` 才拿到这条规则，项目的整个技术核心因此重写。

**还有一条合规硬约束**：只对"用户**已确定要买**的东西"匹配券。券商品不替代任何已购商品时不纳入优化——否则就是诱导加购，赛事规则明令禁止。

### 2. 把口味诉求当硬约束

"A 不吃辣""B 不要酱""C 要换饮料"不是删商品就完事——要落到 `query-meal-detail` 的套餐替换与特调参数上，并遵守它隐晦的传参规则。

### 3. 分账合计分毫不差

用**分**做整数运算 + 最大余额法取整，保证 `sum(每人应付) == 订单总额`，不会出现"最后差一分钱"的尴尬。

```
应付合计  ¥132.50
────────────────
A  ¥33.60    B  ¥37.31    C  ¥24.09
D  ¥21.00    E  ¥16.50
────────────────
合计      ¥132.50   ← 与订单总额一致
```

### 4. 踩过真实工程细节

不是 demo 级别的调用，而是处理了这些真实坑：

| 坑 | 处理 |
|---|---|
| 菜单价格单位是**元**，计价接口返回**分** | 统一转换，不手算 |
| 菜单展示价可能是**随单购价**（需同时买卡） | 自动回退到原价，避免虚假承诺低价 |
| 门店打烊后菜单接口报 `600057` | 下单前先校验营业状态 |
| 同一券 ID 对应多个券码 | 按 `couponId` 分组归一化 |
| 券绑定独立的**券商品码**，拿券套菜单同款报 `600012` | 只点券商品码并联用券码 |
| **一单只能用一张券**（`600022`） | 改用"拆单优化"建模，见下方亮点 1 |
| 券商品可能与它替代的菜单品**规格不同**（券给大薯条、你要的是中薯条） | "省了多少"区分**订单口径**（与账单对齐）与**用户口径**（对外讲省额），并说明规格变化 |
| 到店下单的 `takeWayCode` **不在工具 schema 里枚举**（且 `take-in-store` 字面像堂食、实为外带） | 一律从 `calculate-price` 的 `takeWayList` 取，不硬编码 |
| 同一特调组内多个选项**可能共用同一个 `code`**（可乐的"标准/去冰/多冰/少冰"全是 `200002`） | 靠 `selectedKey` 区分，且每次从 `query-meal-detail` 现取，不写死 |
| 订单状态字段与文档不一致（`orderStatus` 是中文、`status` 数字对不上） | 判断状态只读 `orderStatus` 文本 |
| 下单后金额可能因活动变动而与试算不符 | `order-summary` 自动核对 `realTotalAmount`，不一致即提示可取消订单 |
| 限流 600 次/分钟 | 寻优设探测预算上限（默认 20 次） |

> 以上结论都在**真实下单闭环**中验证过：2026-10-09 至 10-10 实测三次 3 人拼单（含一次**本店无可用券**的情形），完整走完 门店 → 券机会 → 拆单优化 → 分账 → 下单，订单均在麦当劳 App 正常生成待支付，**实付与下单前试算分毫不差**（¥130.90 / ¥84.30 / ¥91.30 三单）。

## 快速开始

### 前置条件

1. 一个麦当劳中国 MCP Token（在 [麦当劳 MCP 开放平台](https://open.mcd.cn/mcp) 手机号登录后，于「控制台」申请）
2. 已安装并支持自定义连接器的 WorkBuddy

### 安装

**第一步：配置 MCP 连接器**

在 WorkBuddy 左侧边栏进入【专家·技能·连接器】→【连接器】→【自定义连接器】→【配置 MCP】，填入：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_TOKEN"
      }
    }
  }
}
```

> ⚠️ 把 `YOUR_MCP_TOKEN` 替换为你的真实 Token，然后保存并**启用**该连接器。

**第二步：安装本 Skill**

把本仓库目录复制到 WorkBuddy 的用户技能目录：

```bash
# macOS / Linux
cp -r mcd-group-order-mate ~/.workbuddy/skills/

# Windows (PowerShell)
Copy-Item -Recurse mcd-group-order-mate "$env:USERPROFILE\.workbuddy\skills\"
```

重启会话后，技能即可被自动识别。

## 工作原理

```
需求收集
   └─ 人数 / 偏好 / 取餐方式  ──→ beType、orderType
门店定位
   └─ query-nearby-stores ──→ 校验营业状态 ──→ storeCode
菜单与券池
   ├─ query-meals         ──→ 菜单 + 价格（校正随单购价）
   ├─ available-coupons   ──→ 麦麦省可领券
   └─ query-store-coupons ──→ 本店可用券池
方案生成
   └─ query-meal-detail   ──→ 套餐替换 / 特调（满足忌口）
券机会挖掘 ★
   ├─ now-time-info          ──→ 定下单时刻
   └─ coupon-opportunities   ──→ 一次调用内完成：按时刻/渠道筛券 + 净收益排序（只列已确定要买的）
券与拆单优化 ★
   ├─ coupon_optimizer.split  ──→ 最大权匹配（匈牙利）+ 多套候选拆法
   ├─ calculate-price × N     ──→ 逐单真实试算（受预算约束）
   └─ coupon_optimizer.select ──→ 取真实总价最低的拆法
分账
   └─ split_bill              ──→ 整数运算 + 最大余额法取整
确认下单
   ├─ create-order            ──→ 用户确认后执行（takeWayCode 取自计价返回）
   └─ order-summary           ──→ 核对实付 == 试算价，不一致即提示可取消
```

## 常见问题

**Q：会不会自动帮我下单？**
不会。创建订单前一定先展示方案并等待你明确确认。

**Q：会不会擅自用我的券？**
不会。领取麦麦省券（`auto-bind-coupons`）属于写操作，会先征求你的同意。

**Q：价格是估算的吗？**
不是。所有金额都来自 `calculate-price` 的真实返回，项目不做任何价格猜测。

**Q：支持外送和团餐吗？**
当前版本以「到店自取」为主链路，外送与团餐按同一参数映射扩展。
