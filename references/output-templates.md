# 输出模板

供 `SKILL.md` 编排时套用，保证每次输出的**结构、口径、金额精度**一致。

## 1. 需求确认单（Phase 0 后回显）

```
【拼单需求确认】
门店     ：麦当劳北京建外SOHO(A座)餐厅（storeCode 1950564）
取餐方式 ：到店自取
人数     ：5 人
偏好     ：A 巨无霸 / B 麦辣鸡腿堡（不吃辣） / C 麦香鱼 / D 板烧鸡腿堡（去酱） / E 麦乐鸡
共享小食 ：一份麦乐鸡
预算     ：无
```

## 2. 拼单方案 + 拆单对比（Phase 4 后输出）★ 核心展示

**前提：一张订单只能用一张券（`600022`）**，所以方案按"一单一券"组织。

```
【麦麦拼单方案】北京建外SOHO店 · 3 人 · 到店自取
──────────────────────────────────────────
 单① 用「麦旋风任选」券
   麦旋风任选1（券商品 9900014239）      1   ¥14.00 → ¥9.90
 单② 用「薯薯任选」券
   薯薯任选（券商品 9900016370）         1   ¥16.00 → ¥9.90
 单③ 无券
   巨无霸三件套                         1              ¥37.50
──────────────────────────────────────────
 不用券合计                                          ¥67.50
 ★ 拆单后应付合计                                    ¥57.30
 券共省 ¥10.20（拆成 3 单；到店自取无配送费，拆单无额外成本）
──────────────────────────────────────────
```

**要点**
- 金额保留两位小数，单位元；券商品要**同时标出券商品码**与"划线价 → 券价"
- 明确写出**拆了几单**以及"拆单无额外成本"的理由（到店自取无配送费）
- **外送场景必须先算每单配送费**：拆单会增加配送费，可能反而更贵，此时应放弃拆单
- 券价必须来自 `calculate-price` 真实试算，**禁止手算或凭券名推测**
- ★ **共享小食要与套餐对账**：套餐自带小食（三件套含中薯条）时，别让共享小食重复同一品类。若为用券而只能重复，用下面这行显式提示：
- ★ **方案必须与预算对账，且把共享项算进人均**：不能只核"每份主食单价 ≤ 人均预算"。共享小食按人均摊后要**逐人**核对，符合就写"人均 ¥X，在预算内"，超出就标"超出 ¥Y"并给一版贴合预算的备选（**不要劝说提高预算**）。实测踩过：三份主食分别 ¥23.90 / ¥26.90 / ¥26.00（都 ≤ 人均 ¥30），加上共享麦乐鸡 ¥14.50 均摊后 B **¥31.73**、C **¥30.83**，两人都超了，方案里却只写了"预算 人均 ¥30 左右"没做核对。

```
> 预算核对：人均预算 ¥30 → 方案人均 ¥30.43
  A ¥28.74 ✅  B ¥31.73 ❌ 超出 ¥1.73  C ¥30.83 ❌ 超出 ¥0.83
  想卡进 ¥30 的话：把共享小食换成更便宜的品类，或给 B 换一款 ¥25 左右的主食。
```

```
⚠️ 提醒：3 份套餐本身已各含一份中薯条，这份共享薯条会与套餐重复（共 4 份薯条）。
   你也可以把共享小食换成套餐没有的品类（如麦乐鸡 ¥14.50），但那样本次没有可用券。
   两条路都给你，你定。
```

## 3. 券机会清单（Phase 2.5 输出）★ 新增

```
【券机会】门店 1950769 · 到店自取 · 下单时刻 2026-10-09 22:23
──────────────────────────────────────────
 ✅ 薯薯任选        划线 ¥16.00 → 券价 ¥9.90    省 ¥6.10
 ✅ 麦旋风任选      划线 ¥14.00 → 券价 ¥9.90    省 ¥4.10
 ⛔ 巧克力味厚松饼  失效原因：限周六 05:00-10:29（当前为周五 22:23）
──────────────────────────────────────────
 合计可省 ¥10.20，需拆成 2 单（一单只能用一张券）
 ⚠️ 上述券今日 23:59 到期，超时后不再可用
```

**要点**
- 每条机会必须带上**券商品码**——用券只能点券商品，不能拿券套菜单同款（会报 `600012`）
- **省额口径**：优先用**用户口径**（被替代菜单品菜单价 − 券价），因为它回答"相比原本要花的钱少花多少"。若券商品与菜单品规格一致，两口径相同；**不一致时必须同时说明规格变化**（如"券给的是大薯条，比原计划的中薯条分量更大"）。订单口径（券商品划线价 − 券价）与之不同，仅用于和账单对齐
- 失效券要**连原因一起展示**（已过期 / 尚未开始 / 限时段 / 限渠道），便于用户自行判断
- ★ `unavailable`（有效期/星期/时段/渠道不通过）与 `notApplicable`（券商品不是用户要买的）**分开列、话术不同**：前者是"这张券此刻/此渠道用不了"，后者是"这张券你用不上"。两者都由**同一次 `coupon-opportunities` 调用**产出，不需要单独跑筛券步骤
- 临界到期（如 <2 小时）必须显式提醒
- ★ 对外说"能省多少"**只能引用 `coupon-opportunities` 的 `totalSavingFen`**——它已剔除"券商品不是用户要买的东西"的券；`excludedSavingFen` 与 `notApplicable` 里的省额**不得**出现在"合计"里
- ★ **禁止诱导加购**：只列用户**已确定要买**的东西所对应的券，不得出现"再加一份就能用券""凑单更省"这类表述

### 3b. 无可用券时的输出（实测高频，必须如实说）

券的商品若都是用户没点的品类（小食/甜品/咖啡），则**没有任何券能用**。此时要**明确说没有**，并给出原因，不能含糊带过：

```
【券机会】门店 3450154 · 到店自取 · 下单时刻 2026-10-09 22:38
──────────────────────────────────────────
 本次没有可用于所选商品的券。
 卡包里这 3 张券（麦旋风任选 / 薯薯任选 / 9.9元冰美式）
 对应的都是小食、甜品、咖啡，替代不了你们要买的主食套餐，
 拆单也凑不出收益（最优解省 ¥0）。
──────────────────────────────────────────
```

**要点**：`split` 返回 `optimalSavingFen == 0` 时即走此模板，**无需再做 oracle 试算**；如实说明后直接进入方案与分账，**绝不**用"要不要加点 X 就能用券"来救场。

## 4. 分账表（Phase 5 输出）

**合计行必须用「订单口径」**——照 `orderDetail.productPrice` / `totalDiscountAmount` / `realTotalAmount` 填，这样群里对着 App 账单能逐行对上：

```
【麦麦拼单分账】
商品原价  ¥137.00
优惠      -¥6.10
  ├ 薯薯任选 -¥6.10（共享小食·按共享规则摊）
实付合计  ¥130.90
────────────────
A  ¥42.13   （麦辣三件套 34.00 + 共享 8.13）
B  ¥43.14   （板烧三件套 35.00 + 共享 8.14）
C  ¥45.63   （巨无霸三件套 37.50 + 共享 8.13）
────────────────
合计      ¥130.90   ← 与订单实付一致

※ 相比原本要买的组合（3 套餐 + 中薯 ¥14.50 + 麦乐鸡 ¥14.50 = ¥135.50）实际少花 ¥4.60；
  券商品是大薯条，比你原计划的中薯条分量更大。
```

**要点**
- 由 `split_bill.py` 生成，**不要手算**——最大余额法保证合计与总额分毫不差
- ★ **`bill.json` 用订单口径填**：券商品按订单原价（薯薯任选 ¥16.00，不是中薯条 ¥14.50），`couponDiscounts.amount` 用订单优惠额（¥6.10）。两种口径的**每人均摊完全相同**，但混用会出现"分账表 ¥135.50 vs App ¥137.00"的对不上
- ★ **券优惠必须按"它作用在哪个商品上"归属**：作用在共享小食上 → 用 `couponDiscounts` 的 `target:"shared"`（跟随共享规则摊）；作用在某人的个人商品上 → `target:"<姓名>"`（全额归该人）。**不要**把券优惠塞进全局 `discount` 用 `proportional` 摊——那会让别人补贴持券人
- "省了多少"**另起一行**并注明基线（用户口径），不要塞进合计行
- 附一句可供直接转发到群里的文案（脚本已内置于 `aaText` 字段）
- 若采用"优惠归发起人"规则，须显式说明，避免误会

## 5. 下单确认卡（Phase 6 前）

```
即将创建订单：
  门店    麦当劳成都天府新区剑南大道得来速餐厅
  取餐    外带
  餐品    5 项 / 共 5 件
  原价    ¥137.00
  优惠    -¥6.10（薯薯任选）
  应付    ¥130.90
确认下单请回复"下单"；需要调整请直接说明。
```

> **未收到用户明确的"下单"字样前，不得调用 `create-order`。**
> 若券临近到期（如 <1 小时），在确认卡里一并提醒。

## 5b. 下单成功汇报（Phase 6 后）★ 字段全部照 `orderDetail` 填

```
订单已生成 ✅
  订单号  1030193170000795583095383781
  门店    麦当劳成都天府新区剑南大道得来速餐厅
  取餐    外带
  商品    麦辣鸡腿汉堡三件套 / 板烧鸡腿堡三件套 / 巨无霸三件套 / 麦乐鸡5块 / 薯薯任选（券）
  原价    ¥137.00
  优惠    -¥6.10（薯薯任选券）
  实付    ¥130.90
  时限    23:23 前（15 分钟）

  支付：https://m.mcd.cn/mcp/scanToPay?orderId=1030193170000795583095383781

  ※ 相比原本要买的组合（3 套餐 + 中薯条 + 麦乐鸡 ¥135.50），实际少花 ¥4.60；
    券商品是大薯条，规格比你原计划的中薯条更大。
```

**要点**
- **必须先核对 `realTotalAmount` 与下单前试算价**；不一致要告知差异并给出 `cancel-order` 选项
- 时限用 `expirePayTime`（实测下单后 15 分钟）；提示"超时订单会失效，需要取消请说一声"
- 商品清单可用 `orderProductList[].comboItemList` 补充套餐子项，便于用户核对
- ★ **末尾必须有"省了多少"一行**（用户口径 + 基线 + 规格变化说明）——`SKILL.md` Phase 5 要求它有独立行，别只在方案阶段说过、下单汇报里就丢掉
- 支付完成后回复"支付完成"，用 `query-order` 查最新状态

| 共享小食与套餐重复 | "你的 N 份套餐本身已各含{套餐小食}，这份共享{小食}会重复。保留它（能用券省 ¥{X}）还是换成套餐没有的品类（本次无券可用）？两条都行，你定。" |
